# Руководство по защите Лабораторной работы №3: «Работа с данными» (ASP.NET Core MVC)

## Раздел 1. Теоретический фундамент

Чтобы сдать лабораторную работу на высший балл, нужно понимание архитектурных паттернов и механизмов ASP.NET Core MVC, использованных в проекте.

### 1.1. Архитектурная многослойность (Clean Architecture / Layered Architecture)
Проект разделен на отдельные модули (проекты/слои):
1. **Domain (`labs.Domain`)**: Содержит бизнес-сущности (`Entities`) и модели передаваемых данных (`Models`). Это «сердце» приложения, оно не зависит от внешних библиотек или веб-фреймворка.
2. **Services (`labs.Services` / `labs/Services`)**: Слой бизнес-логики. Содержит интерфейсы и реализации сервисов, отвечающих за получение, фильтрацию и пагинацию данных.
3. **UI / Presentation (`labs`)**: Веб-приложение ASP.NET Core MVC (Контроллеры, Представления Razor, Расширения, Настройки).

---

### 1.2. Внедрение зависимостей (Dependency Injection — DI) и IoC-контейнер
**Dependency Injection (DI)** — это паттерн проектирования, при котором класс не создает свои зависимости сам (через `new`), а получает их извне (через конструктор).
* **Inversion of Control (IoC)** — принцип, при котором управление созданием объектов передается фреймворку (IoC-контейнеру ASP.NET Core).

#### Время жизни сервисов (Service Lifetimes):
* **Transient (`AddTransient`)**: Новый экземпляр создается **каждый раз**, когда происходит обращение к сервису.
* **Scoped (`AddScoped`)**: Один экземпляр создается **на каждый HTTP-запрос**. В рамках одного запроса все компоненты получают один и тот же объект. (Используется для сервисов данных в MVC).
* **Singleton (`AddSingleton`)**: Один экземпляр создается при старте приложения и живет **все время работы сервера**.

---

### 1.3. Шаблон «Обертка ответа» (ResponseData<T>)
Вместо того чтобы возвращать сырые данные или бросать исключения (`Exception`), сервисы возвращают унифицированный объект-контейнер `ResponseData<T>`.
* Содержит сами данные (`Data`), флаг успеха (`Successfull`) и сообщение об ошибке (`ErrorMessage`).
* Это гарантирует устойчивость приложения: контроллер всегда получает понятный ответ и обработанный статус выполнения.

---

### 1.4. Связывание моделей (Model Binding) и передача данных
* **Model Binding**: Автоматический процесс ASP.NET Core, который берет данные из HTTP-запроса (Query string, Route data, Form data, Headers) и подставляет их в параметры методов контроллера (`Action`).
* **ViewData / ViewBag**: Словари/динамические свойства для передачи нетипизированных вспомогательных данных из Контроллера в Представление (например, список категорий для выпадающего меню).
* **Strongly Typed View (Сильнотипизированное представление)**: Представление объявляет класс модели через директиву `@model ListModel<Dish>`. Это дает строгое соответствие типов, автодополнение (IntelliSense) и проверку ошибок на этапе компиляции.

---

### 1.5. Таг-хелперы (Tag Helpers) и явные выражения Razor
* **Tag Helpers**: Специальные C#-атрибуты в HTML-тегах (начинаются с `asp-`), которые исполняются на сервере и генерируют валидный HTML.
  * `asp-controller="Product"` — указывает контроллер.
  * `asp-action="Index"` — указывает действие.
  * `asp-route-category="soups"` — формирует GET-параметр или часть маршрута `?category=soups`.
* **Явное выражение Razor (Explicit Razor Expression)**: Выражение вида `@(выражение)`, обернутое в скобки. Применяется, когда C#-код граничит с контентом или требует четкого указания границ выполнения (например: `@(Model.CurrentPage == 1 ? "disabled" : "")`).

---

### 1.6. LINQ: Фильтрация и Пагинация
* **Фильтрация (`.Where(...)`)**: Отбирает элементы по условию.
* **Пропуск элементов (`.Skip(n)`)**: Пропускает первые $n$ элементов списка.
* **Взятие элементов (`.Take(m)`)**: Берет следующие $m$ элементов списка.
* **Формула расчета пропуска**: $\text{SkipCount} = (\text{pageNo} - 1) \times \text{pageSize}$.
* **Формула расчета общего числа страниц**: $\text{TotalPages} = \lceil \frac{\text{TotalItems}}{\text{PageSize}} \rceil$, реализация на C#: `(int)Math.Ceiling((double)count / pageSize)`.

### 📄 Файл 3: `labs.Domain/Models/ResponseData.cs`
**Назначение**: Универсальный дженерик-класс (Generic) для обертывания ответов от сервисов.

```csharp
namespace labs.Domain.Models;

public class ResponseData<T>
{
    public T? Data { get; set; }                          // Запрашиваемые данные произвольного типа T
    
    public bool Successfull { get; set; } = true;         // Флаг: успешно ли выполнен запрос
    
    public string? ErrorMessage { get; set; }             // Текст ошибки (если Successfull = false)
    
    // Статический фабричный метод для создания успешного ответа
    public static ResponseData<T> Success(T data)
    {
        return new ResponseData<T> { Data = data };
    }
    
    // Статический фабричный метод для создания ответа с ошибкой
    public static ResponseData<T> Error(string message, T? data = default)
    {
        return new ResponseData<T>
        {
            ErrorMessage = message,
            Successfull = false,
            Data = data
        };
    }
}
```
* **Зачем нужны фабричные методы?**: Статические методы `Success` и `Error` инкапсулируют логику создания объекта и делают код вызова чистым и понятным.

### 📄 Файл 9: `labs/Services/ProductService/MemoryProductService.cs`
**Назначение**: Тестовая (In-Memory) реализация сервиса продуктов с поддержкой фильтрации и пагинации LINQ.

```csharp
using labs.Models;
using Microsoft.AspNetCore.Mvc;

namespace labs.Services;

public class MemoryProductService : IProductService
{
    private readonly IConfiguration _config;              // Доступ к конфигурации (appsettings.json)
    private readonly ICategoryService _categoryService;   // Сервис категорий для связывания
    private List<Dish> _dishes = new();                   // Внутреннее хранилище блюд

    // Конструктор с внедрением зависимостей
    public MemoryProductService(
        [FromServices] IConfiguration config, 
        ICategoryService categoryService)
    {
        _config = config;
        _categoryService = categoryService;
        SetupData(); // Заполнение начальными данными при создании сервиса
    }

    public Task<ResponseData<ListModel<Dish>>> GetProductListAsync(string? categoryNormalizedName, int pageNo = 1)
    {
        // 1. ФИЛЬТРАЦИЯ
        // Если categoryNormalizedName == null -> берутся все блюда.
        // Иначе сравнивается NormalizedName категории без учета регистра (StringComparison.OrdinalIgnoreCase)
        var data = _dishes
            .Where(d => categoryNormalizedName == null || 
                        d.Category?.NormalizedName.Equals(categoryNormalizedName, StringComparison.OrdinalIgnoreCase) == true)
            .ToList();

        // 2. ПОЛУЧЕНИЕ РАЗМЕРА СТРАНИЦЫ ИЗ APPSETTINGS.JSON
        // Если ключ "ItemsPerPage" отсутствует, по умолчанию берется 3
        int pageSize = _config.GetValue<int>("ItemsPerPage", 3);

        // 3. РАСЧЕТ ОБЩЕГО КОЛИЧЕСТВА СТРАНИЦ
        int totalPages = (int)Math.Ceiling((double)data.Count / pageSize);

        // 4. ПАГИНАЦИЯ (Skip и Take)
        var items = data
            .Skip((pageNo - 1) * pageSize) // Пропускаем элементы предыдущих страниц
            .Take(pageSize)               // Берем элементы для текущей страницы
            .ToList();

        // Формируем результат
        var model = new ListModel<Dish>
        {
            Items = items,
            CurrentPage = pageNo,
            TotalPages = totalPages
        };

        return Task.FromResult(ResponseData<ListModel<Dish>>.Success(model));
    }

    // Заглушки для CRUD-методов
    public Task<ResponseData<Dish>> GetProductByIdAsync(int id) => throw new NotImplementedException();
    public Task UpdateProductAsync(int id, Dish product, IFormFile? formFile) => throw new NotImplementedException();
    public Task DeleteProductAsync(int id) => throw new NotImplementedException();
    public Task<ResponseData<Dish>> CreateProductAsync(Dish product, IFormFile? formFile) => throw new NotImplementedException();

    // Инициализация стартового набора данных
    private void SetupData()
    {
        var categories = _categoryService.GetCategoryListAsync().Result.Data;

        _dishes = new List<Dish>
        {
            new Dish 
            { 
                Id = 1, 
                Name = "Суп-харчо", 
                Description = "Очень острый, вкусный", 
                Calories = 200, 
                Image = "images/Харчо.jpg", 
                Category = categories?.Find(c => c.NormalizedName.Equals("soups")) 
            },
            new Dish 
            { 
                Id = 2, 
                Name = "Борщ", 
                Description = "Много сала, без сметаны", 
                Calories = 330, 
                Image = "images/Борщ.jpg", 
                Category = categories?.Find(c => c.NormalizedName.Equals("soups")) 
            },
            new Dish 
            { 
                Id = 3, 
                Name = "Цезарь", 
                Description = "Классический салат с куриным филе", 
                Calories = 250, 
                Image = "images/Цезарь.jpg", 
                Category = categories?.Find(c => c.NormalizedName.Equals("salads")) 
            },
            new Dish 
            { 
                Id = 4, 
                Name = "Стейк Рибай", 
                Description = "Сочное мясо со специями", 
                Calories = 500, 
                Image = "images/Стейк.jpg", 
                Category = categories?.Find(c => c.NormalizedName.Equals("main-dishes")) 
            },
            new Dish 
            { 
                Id = 5, 
                Name = "Лимонад", 
                Description = "Освежающий цитрусовый напиток", 
                Calories = 120, 
                Image = "images/Лимонад.jpg", 
                Category = categories?.Find(c => c.NormalizedName.Equals("drinks")) 
            }
        };
    }
}
```

### 📄 Файл 10: `labs/Extensions/HostingExtensions.cs`
**Назначение**: Метод расширения для регистрации сервисов в IoC-контейнере ASP.NET Core.

```csharp
using labs.Models;
using labs.Services;
using labs.Services.CategoryService;
using labs.Services.ProductService;

namespace labs.Extensions;

public static class HostingExtensions
{
    // Метод расширения для WebApplicationBuilder
    public static void RegisterCustomServices(this WebApplicationBuilder builder)
    {
        // Примечание: В текущей версии кода вызовы Memory-сервисов закомментированы,
        // так как проект эволюционировал в сторону работы с Web API через HttpClient.
        // builder.Services.AddScoped<ICategoryService, MemoryCategoryService>();
        // builder.Services.AddScoped<IProductService, MemoryProductService>();
        
        // Чтение конфигурационной секции "UriData"
        var uriData = builder.Configuration.GetSection("UriData").Get<UriData>()
                      ?? throw new InvalidOperationException("В appsettings.json нет секции UriData");

        // Регистрация Typed HttpClient для IProductService и ICategoryService
        var productClient = builder.Services.AddHttpClient<IProductService, ApiProductService>(opt =>
            opt.BaseAddress = new Uri(uriData.ApiUri + "dish/"));

        var categoryClient = builder.Services.AddHttpClient<ICategoryService, ApiCategoryService>(opt =>
            opt.BaseAddress = new Uri(uriData.ApiUri + "categories/"));

        // Настройка игнорирования ошибок самоподписанных SSL-сертификатов в среде Development (актуально на Linux/macOS)
        if (builder.Environment.IsDevelopment())
        {
            HttpMessageHandler DevHandler() => new HttpClientHandler
            {
                ServerCertificateCustomValidationCallback =
                    HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
            };
            productClient.ConfigurePrimaryHttpMessageHandler(DevHandler);
            categoryClient.ConfigurePrimaryHttpMessageHandler(DevHandler);
        }
    }
}
```

### 📄 Файл 13: `labs/Controllers/ProductController.cs`
**Назначение**: Контроллер каталога товаров. Принимает HTTP-запросы, взаимодействует с сервисами и отдает заполненное Представление.

```csharp
using Microsoft.AspNetCore.Mvc;

namespace labs.Controllers;

public class ProductController : Controller
{
    private readonly IProductService _productService;
    private readonly ICategoryService _categoryService;

    // Внедрение зависимостей через конструктор (Constructor DI)
    public ProductController(IProductService productService, ICategoryService categoryService)
    {
        _productService = productService;
        _categoryService = categoryService;
    }

    // Action-метод Index: аргументы заполняются через Model Binding из query-строки: ?category=...&pageNo=...
    public async Task<IActionResult> Index(string? category, int pageNo = 1)
    {
        // 1. Запрос списка всех категорий для выпадающего списка
        var categoriesResponse = await _categoryService.GetCategoryListAsync();
        if (!categoriesResponse.Successfull)
        {
            return NotFound(categoriesResponse.ErrorMessage);
        }

        var categories = categoriesResponse.Data;
        ViewData["categories"] = categories; // Передача списка категорий во ViewData

        // 2. Определение человекопонятного имени выбранной категории
        var currentCategory = categories.FirstOrDefault(c => 
            c.NormalizedName.Equals(category, StringComparison.OrdinalIgnoreCase))?.Name ?? "Все";
        ViewData["currentCategory"] = currentCategory; // Передача названия текущей категории

        // 3. Запрос товаров с учетом фильтра и текущей страницы
        var productResponse = await _productService.GetProductListAsync(category, pageNo);
        if (!productResponse.Successfull)
        {
            return NotFound(productResponse.ErrorMessage);
        }

        // 4. Передача модели ListModel<Dish> в представление Index.cshtml
        return View(productResponse.Data);
    }
}
```

## Раздел 3. Как работает запрос: пошаговая цепочка execution flow

Представим, что пользователь открыл ссылку: `http://localhost:5000/Product?category=soups&pageNo=2`.

```
[Браузер (HTTP GET)] 
       │
       ▼
[Kestrel Server & Middleware] (UseRouting, UseStaticFiles)
       │
       ▼
[Model Binding] ──► Автоматически извлекает: category="soups", pageNo=2
       │
       ▼
[ProductController.Index(category, pageNo)]
       ├─► 1. Вызывает _categoryService.GetCategoryListAsync()
       ├─► 2. Кладет категории и currentCategory во ViewData
       ├─► 3. Вызывает _productService.GetProductListAsync("soups", 2)
       │        │
       │        └─► [MemoryProductService / ApiProductService]
       │               ├─ Фильтрует список по categoryNormalizedName = "soups"
       │               ├─ Берет ItemsPerPage из appsettings.json (3)
       │               ├─ Считает TotalPages: Ceiling(Count / 3)
       │               └─ Выполняет LINQ: .Skip((2-1)*3).Take(3)
       │
       ├─► 4. Получает ResponseData<ListModel<Dish>>
       └─► 5. Возвращает View(responseData.Data)
       │
       ▼
[Razor Engine (Index.cshtml)] 
       ├─ Генерирует HTML на основе ListModel<Dish>
       └─ Применяет Tag Helpers для формирования ссылок
       │
       ▼
[HTML Ответ отправляется Клиенту]
```

## Раздел 4. Ответы на контрольные вопросы лабораторной работы

### Вопрос 1: Как зарегистрировать сервис в ASP.Net Core?
**Ответ:**
Сервисы регистрируются в IoC-контейнере через коллекцию `builder.Services` в файле `Program.cs` (или через методы расширения, такие как `RegisterCustomServices`). Для этого используются методы с указанием времени жизни:
* `builder.Services.AddTransient<IInterface, Implementation>();`
* `builder.Services.AddScoped<IInterface, Implementation>();`
* `builder.Services.AddSingleton<IInterface, Implementation>();`

---

### Вопрос 2: Чем отличается Transient сервис от Scoped сервиса?
**Ответ:**
* **Transient**: Создает новый объект **при каждом обращении** к нему в коде (каждый раз, когда он запрашивается как зависимость).
* **Scoped**: Создает один единственный объект **на весь период обработки одного HTTP-запроса**. Все компоненты, запрашивающие этот сервис в рамках обработки текущего HTTP-запроса, получат один и тот же экземпляр.

---

### Вопрос 3: Как внедрить сервис в метод (Action) контроллера?
**Ответ:**
Есть два основных способа:
1. **Через конструктор контроллера (Рекомендуемый)**:
   ```csharp
   public class ProductController : Controller {
       private readonly IProductService _service;
       public ProductController(IProductService service) => _service = service;
   }
   ```
2. **Напрямую в параметр Action-метода** с помощью атрибута `[FromServices]`:
   ```csharp
   public IActionResult Index([FromServices] IProductService service) { ... }
   ```

---

### Вопрос 4: Как передать данные от клиента в метод контроллера?
**Ответ:**
Данные передаются от клиента через HTTP-запрос следующими способами:
1. **Query String (строка запроса)**: `/Product?category=soups&pageNo=2`.
2. **Route Data (параметры маршрута)**: `/Product/Index/5`.
3. **Form Data (тело HTTP POST-запроса)**: передача формы.
4. **HTTP Headers / Body (JSON)**: для REST API.

ASP.NET Core автоматически считывает их с помощью механизма **Model Binding**.

---

### Вопрос 5: Где механизм привязки (Model binding) ищет нужные значения?
**Ответ:**
По умолчанию механизм Model Binding ищет значение в следующем порядке:
1. Поля формы (`Form fields`) — данные из POST-запроса.
2. Тело запроса (`Request body`) — если настроен соответсвующий форматтер.
3. Данные маршрута (`Route values`) — значения из шаблона URL.
4. Строка запроса (`Query string parameters`) — параметры после знака `?`.
5. Загруженные файлы (`Header / Form Files`).

При необходимости источник можно указать явно атрибутами `[FromQuery]`, `[FromRoute]`, `[FromBody]`, `[FromForm]`, `[FromHeader]`.

---

### Вопрос 6: Как получить данные из файла appsettings.json?
**Ответ:**
Через сервис конфигурации `IConfiguration`, который доступен по умолчанию через DI:
1. **Метод `GetValue<T>`**:
   ```csharp
   int pageSize = _config.GetValue<int>("ItemsPerPage", 3);
   ```
2. **Метод `GetSection`**:
   ```csharp
   var uriData = _config.GetSection("UriData").Get<UriData>();
   ```

---

### Вопрос 7: Как передать данные с помощью IOptions?
**Ответ:**
Паттерн **Options** позволяет привязать секцию конфигурации из `appsettings.json` к C#-классу.
1. Создаем класс настроек:
   ```csharp
   public class UriData { public string ApiUri { get; set; } }
   ```
2. Регистрируем связывание в `Program.cs`:
   ```csharp
   builder.Services.Configure<UriData>(builder.Configuration.GetSection("UriData"));
   ```
3. Внедряем `IOptions<UriData>` в нужный сервис или контроллер:
   ```csharp
   public class ApiProductService {
       public ApiProductService(IOptions<UriData> options) {
           var uri = options.Value.ApiUri;
       }
   }
   ```

---

### Вопрос 8: Как в коде прочитать значение, передаваемое в строке запроса?
**Ответ:**
1. **Через параметры Action-метода контроллера (Model Binding)**:
   ```csharp
   public IActionResult Index(string? category) { ... }
   ```
2. **Напрямую из `HttpContext`**:
   ```csharp
   string? category = HttpContext.Request.Query["category"].ToString();
   ```

---

### Вопрос 9: Как в тэге `<a>` передать в запрос дополнительные данные с помощью tag-helper?
**Ответ:**
С помощью атрибута `asp-route-{parameterName}`. Например, чтобы передать параметр `pageNo=2` и `category=soups`:
```html
<a asp-controller="Product" 
   asp-action="Index" 
   asp-route-pageNo="2" 
   asp-route-category="soups">Страница 2</a>
```
При рендеринге это превратится в HTML: `<a href="/Product?category=soups&pageNo=2">Страница 2</a>`.

---

### Вопрос 10: Что такое «Явное выражение Razor»?
**Ответ:**
**Явное выражение Razor (Explicit Razor Expression)** — это конструкция Razor вида `@(C# выражение)`, где выражение явно заключено в скобки.

Это необходимо, чтобы устранить неоднозначность при синтаксическом анализе, когда C#-код находится непосредственно перед символом или текстом без пробела, либо при использовании сложных тернарных операторов.

**Пример:**
```html
<!-- Без явного выражения Razor вызовет ошибку парсера -->
<li class="page-item @(Model.CurrentPage == 1 ? "disabled" : "")">

<!-- Конкатенация текста и кода -->
<span>Всего: @(count)шт.</span>
```

## Раздел 5. Итоговая шпаргалка для быстрой повторной проверки

* **За что отвечает `ListModel<T>`?** Хранит список отображаемых элементов, номер текущей страницы (`CurrentPage`) и их общее число (`TotalPages`).
* **За что отвечает `ResponseData<T>`?** Обертка для всех ответов сервисов. Хранит данные (`Data`), флаг успеха (`Successfull`) и ошибки (`ErrorMessage`).
* **Как работает пагинация в C#?** Применяются методы LINQ: `.Skip((pageNo - 1) * pageSize).Take(pageSize)`.
* **Зачем `NormalizedName`?** Для человекочитаемых и безопасных адресов категории в адресной строке (`/Product?category=soups`).
* **Как передаются категории во View?** Через словарь `ViewData["categories"]` и `ViewData["currentCategory"]`.
* **Какой Lifetime у сервисов в MVC?** Как правило, `Scoped` (`AddScoped`), так как сервисы привязаны к контексту текущего HTTP-запроса.
