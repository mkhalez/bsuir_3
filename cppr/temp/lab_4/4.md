## 1. Теоретическая база: Что вообще здесь происходит?

В этой лабораторной мы строим **клиент-серверную архитектуру** с использованием REST API и базы данных. 

*   **REST API (Representational State Transfer)** — это архитектурный стиль взаимодействия компонентов. Если проще: это набор правил (URL-адресов), по которым одна программа (наш UI-проект) может просить другую программу (наш API-проект) дать ей данные, сохранить их, изменить или удалить. Общение идет в формате JSON.
*   **HTTP-методы** — глаголы, которые говорят API, что нужно сделать:
    *   `GET` — получить данные (список блюд).
    *   `POST` — создать новую запись (добавить блюдо).
    *   `PUT` — обновить существующую запись.
    *   `DELETE` — удалить запись.
*   **Entity Framework Core (EF Core)** — это ORM (Object-Relational Mapper). Штука, которая позволяет нам писать код на C# (работать с классами `Dish`, `Category`), а она сама переводит этот код в SQL-запросы к базе данных PostgreSQL.
*   **Minimal API vs Controllers** — два способа создать API в .NET. 
    *   *Контроллеры* — классический, громоздкий способ (классы наследуются от `ControllerBase`). В лабе используется для `CategoriesController`.
    *   *Minimal API* — современный, легкий способ, где функции привязываются прямо к URL-адресам (`app.MapGet(...)`). В лабе используется для `DishEndpoints`.
*   **MediatR** — библиотека для реализации паттерна "Посредник". Она помогает разделить код: тот, кто принимает запрос (Endpoint), ничего не знает о том, как достать данные из БД. Он просто отправляет "Сообщение" в MediatR, а MediatR находит нужный "Обработчик" (Handler), который и выполняет грязную работу.

## 2. Общий механизм работы (Архитектура)

Как данные попадают на экран браузера:
1.  **БД PostgreSQL** (крутится в контейнере Docker) хранит таблички с едой и категориями.
2.  **API-проект (`labs.API`)** подключается к БД через EF Core. Он выставляет наружу "ручки" (endpoints), например: `https://localhost:7002/api/Dish`.
3.  **UI-проект (`labs.UI`, клиент)** хочет показать меню. Он берет `HttpClient` и отправляет HTTP-запрос `GET /api/Dish` на сервер API.
4.  API идет в базу, достает блюда, упаковывает их в JSON и отправляет обратно UI-проекту.
5.  UI-проект распаковывает JSON, превращает его в C#-объекты и рендерит HTML-страницу для пользователя.

    *   Проверяет, есть ли категории. Если нет — через `context.Categories.Add(...)` добавляет их. Заметь, мы не указываем `Id`, база сгенерирует их сама.
    *   Сохраняет изменения: `await context.SaveChangesAsync()`.

### Блок 3: API Контроллеры и Minimal API

**Файл: `labs.API/Controllers/CategoriesController.cs` (Классический контроллер)**
```csharp
[Route("api/[controller]")] // Путь будет /api/Categories
[ApiController] // Включает автоматические проверки (например, валидацию моделей)
public class CategoriesController : ControllerBase
{
    private readonly AppDbContext _context; // Получаем доступ к БД
    // ... конструктор ...
    
    [HttpGet] // Этот метод сработает при GET-запросе
    public async Task<ActionResult<IEnumerable<Category>>> GetCategories()
    {
        return await _context.Categories.ToListAsync(); // Достаем все категории из БД
    }
}
```
*   **Зачем нужен:** Это стандартный сгенерированный (scaffolded) контроллер для CRUD-операций над категориями. Возвращает данные в виде JSON.

**Файл: `labs.API/EndPoints/DishEndpoints.cs` (Minimal API)**
```csharp
public static void MapDishEndpoints(this IEndpointRouteBuilder routes)
{
    // Группируем все маршруты под префиксом "/api/Dish"
    var group = routes.MapGroup("/api/Dish").DisableAntiforgery();

    // GET /api/Dish/{category} - получение списка блюд
    group.MapGet("/{category:alpha?}", async (
        IMediator mediator, string? category, int pageNo = 1, int pageSize = 3) =>
    {
        // Вместо того чтобы лезть в БД тут, мы отправляем запрос в MediatR!
        var data = await mediator.Send(new GetListOfProducts(category, pageNo, pageSize));
        return TypedResults.Ok(data); // Возвращаем статус 200 OK и данные
    }).WithName("GetAllDishes");
    
    // ... тут дальше MapPost (создание), MapPut (обновление), MapDelete (удаление)
}
```
*   **Зачем нужен:** Это реализация Minimal API. Кода меньше, чем в контроллерах. Обрати внимание, что для логики фильтрации и пагинации используется `MediatR`.

### Блок 4: Бизнес-логика (MediatR)

**Файл: `labs.API/Use-Cases/GetListOfProducts.cs`**
*   **Зачем нужен:** Изолирует сложную логику запроса к БД (пагинация, фильтрация).
*   **`GetListOfProducts` (record):** Это просто класс-сообщение (запрос). В нем лежат параметры: имя категории, номер страницы. Наследуется от `IRequest<ТипВозвращаемогоЗначения>`.
*   **`GetListOfProductsHandler` (class):** Это обработчик. Когда кто-то вызывает `mediator.Send(new GetListOfProducts(...))`, MediatR находит этот хэндлер и запускает метод `Handle`.
*   **Внутри метода `Handle`:**
    *   `IQueryable<Dish> query = db.Dishes.AsNoTracking();` — создаем запрос к БД (не отслеживая изменения для скорости).
    *   `query.Where(d => d.Category!.NormalizedName == request.CategoryNormalizedName)` — фильтруем, если передана категория.
    *   `.Skip((pageNo - 1) * pageSize).Take(pageSize)` — классическая математика пагинации (пропускаем N элементов, берем M).

## 4. Ответы на контрольные вопросы

1.  **Чем контроллер API отличается от обычного контроллера?**
    *   Обычный контроллер (MVC) возвращает представления (Views/HTML-страницы) с помощью метода `View()`. Контроллер API возвращает "голые" данные (обычно в формате JSON) и использует атрибут `[ApiController]`.
2.  **Как осуществляется выбор метода (Action) контроллера API при обработке запроса Http?**
    *   Выбор метода осуществляется системой маршрутизации (Routing) на основе двух вещей: URL-адреса запроса и типа HTTP-метода (GET, POST, PUT, DELETE), которые указываются атрибутами над методами (например, `[HttpGet("{id}")]`).
3.  **Где в запросе и в каком виде передаются данные в контроллер API?**
    *   Данные могут передаваться:
        *   В **строке запроса (Query String)** — после знака `?` (например, `?pageSize=3`).
        *   В **сегментах пути (Route parameters)** — прямо в URL (например, `/api/Dish/5`).
        *   В **теле запроса (Body)** — чаще всего в формате JSON для сложных объектов (при POST/PUT). Указывается атрибутом `[FromBody]`.
        *   Через формы (Form data) — например, для загрузки файлов `[FromForm]`.
4.  **Как в коде получить Scoped сервис?**
    *   Внутри контроллеров или Minimal API они автоматически внедряются (Dependency Injection) через параметры метода или конструктора. Если нужно получить сервис вручную вне запроса (как в `DbInitializer`), создается область видимости: `using var scope = app.Services.CreateScope();` и сервис достается через `scope.ServiceProvider.GetRequiredService<T>()`.
5.  **Что могут возвращать методы контроллера API?**
    *   Могут возвращать конкретные типы данных (например, `List<Dish>`), объекты `IActionResult` (результаты вроде `Ok()`, `NotFound()`, `BadRequest()`) или `ActionResult<T>` (комбинация первых двух вариантов).
6.  **Что такое Minimal API?**
    *   Это легковесный способ создания конечных точек (endpoints) HTTP-сервисов в ASP.NET Core без необходимости создавать громоздкие классы-контроллеры. Функции-обработчики привязываются напрямую к URL в классе `Program`.
7.  **Как зарегистрировать конечную точку для Minimal API?**
    *   Используя методы-расширения экземпляра `WebApplication` (или `IEndpointRouteBuilder`), такие как `app.MapGet("путь", обработчик)`, `app.MapPost()`, `app.MapPut()`, `app.MapDelete()`.
8.  **Как зарегистрировать группу конечных точек для Minimal API?**
    *   Используя метод `MapGroup()`. Например: `var group = app.MapGroup("/api/Dish");`. После этого маршруты привязываются к этой группе: `group.MapGet("/", ...)` (реальный путь будет `/api/Dish/`).

## 5. Саммари (Краткая выжимка для защиты)

*   **Суть лабы:** Разделили проект на Клиент (UI) и Сервер (API). Добавили реальную БД PostgreSQL.
*   **Связь:** UI-проект общается с API-проектом по сети (по HTTP) с помощью встроенного класса `HttpClient`.
*   **Формат данных:** Данные между ними летают в формате JSON.
*   **API:** Сделан двумя путями: Categories — через Контроллеры, Dishes — через Minimal API. 
*   **БД:** Работает через EF Core (Code First). Мы описали классы, EF Core сам сделал таблицы (через миграции) и переводит LINQ запросы в SQL.
*   **MediatR:** Библиотека, реализующая паттерн CQRS. Отделяет место приема HTTP-запроса от бизнес-логики (запросов в базу).
